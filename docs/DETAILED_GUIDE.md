# OKR Cascade & Challenge Skills — DeepSeek edition

Version: 2.0 (2026-11-24). Язык ответов — русский. Универсальный набор для владельцев продуктов и СРО.

## Цель

Создать проверяемый процесс **TOP OKR → CPO/СРО OKR → Product/Team OKR → инициативы → эпики → PRD → stories → acceptance criteria**. Проверять полноту каскада, расхождения, конкурирующие KR, зависимости, измеримость, ёмкость; задавать короткие вопросы вместо выдумывания фактов. Сохранять авторство и исходные формулировки.

## Совместимость с DeepSeek

- Это **переносимые Markdown-инструкции** `SKILL.md`. В DeepSeek Chat их можно прикладывать как файлы/вставлять текст; этапы вызываются отдельными запросами по `workflows/manual-run.md`.
- Для автоматизации через **DeepSeek API** есть `scripts/run_api.py` (требует `pip install openai`, ключ `DEEPSEEK_API_KEY`, доступ к API). Скрипт передаёт входные текстовые источники и запускает stages последовательно, сохраняет ответы локально и **останавливается на проверке человека**. 
- Для DeepSeek через агентный клиент, умеющий читать локальные `SKILL.md` (например, совместимый инструмент), можно разместить содержимое `skills/*/SKILL.md` в принятой клиентом структуре. Поддержка автоматического вызова зависит от клиента, не от самой модели.

## Входные материалы (не обязательны все сразу)

1. Исходные TOP OKR с названиями метрик, владельцами и целями.
2. Стратегия/позиционирование, результаты предыдущего года (факт отдельно от плана).
3. Предложения СРО и команды, норматив KPI/RUN, карта оргответственности.
4. Общий файл целей с KR и подписями **всех** участников.
5. Бэклог, эпики, архитектура AS-IS, загрузка по ролям и связи с командами.
6. Паспорта метрик, события/инциденты, подтверждения связей с FP и бизнес-эффектом.

Если Excel используется как источник, извлечь нужные ячейки с адресами и авторами командой `python scripts/extract_xlsx.py file.xlsx > sources.txt`. **Внимание:** эта утилита извлекает текст и адреса, не заменяет чтение rich-text-цветов. Цвета ФИО и авторство проверяются отдельно человеком; нельзя восстанавливать авторство по догадке.

## Порядок выполнения

| Этап | Skill | Артефакт | Stop condition |
|---|---|---|---|
| 0 | `00-source-intake` | `source_register.md`, факты/планы/гипотезы | Конфликт версий не разрешён |
| 1 | `01-discovery-questions` | вопросы и `decision_register.md` | Нет критичной информации для ownership/метрики |
| 2 | `02-okr-design` | проект OKR СРО/команды + паспорта | KR не измерим |
| 3 | `03-cascade-traceability` | матрица трассировки с evidence | Отсутствует обязательный вклад или причинная связь |
| 4 | `04-collision-check` | матрица пересечений / RACI | Есть двойной счёт или конфликт владельцев |
| 5 | `05-capacity-and-initiatives` | объём инициатив, оценка ресурсов | Нагрузка >100% без сокращения scope |
| 6 | `06-audit-and-defense` | PASS/CONDITIONAL/FAIL, правки | Остались критичные FAIL |

Дополнительно: `templates/*.md` — форматы выхода, `examples/fictional-service-case.md` — синтетический пример, `workflows/manual-run.md` — ручная инструкция.

## Принципы, обязательные для всех skills

- **Не изобретать метрики и цифры:** неизвестную цель обозначать `X`, неизвестную базу `н/и`, дату `TBD`. Если численная цель нужна — метод её расчёта, а не произвольный процент.
- **Не заменять source of truth:** различать `ФАКТ`, `ПЛАН`, `ГИПОТЕЗА`, `ТРЕБУЕТ ПОДТВЕРЖДЕНИЯ`. Источник — `файл/лист/ячейка` или цитата/ссылка.
- **Causal link, not thematic link:** похожее название не равно доказанному вкладу в KR руководителя.
- **Не делить общую метрику дважды:** один outcome может иметь много contributors, но один accountable owner и одну методику.
- **Никаких обещаний за внешнюю организацию:** владение пилотом/предложением ≠ право навязать SLA поставщику или изменить требования госорганов.
- **Совпадение сигналов ≠ доказательство причины**; количество затронутых вычислений ≠ число уникальных решений; доступность ПО ≠ корректность бизнес-результата.
- **Годовые цели — результаты года, квартальные — этапы**. Инициатива, таск или документ сами по себе не outcome KR.
- **Не трогать чужие ячейки и цвета подписей в общем файле.** Перед любой записью создать diff/копию; авторское цветовое форматирование rich text — отдельная проверка.
- **Не грузить конфиденциальные корпоративные данные в публичный DeepSeek без разрешения ИБ.** Для таких документов используйте разрешённый корпоративный шлюз/локальный контур и обезличивание.

## Проверка качества набора

Можно вручную прогнать `examples/fictional-service-case.md`, а локально проверить схему артефактов командой `python scripts/validate_trace.py examples/sample_trace.json`. Скрипт гарантирует структурную корректность и базовое наличие связей, **не подтверждает причинность**: последняя — проверка модели + человека.

# V2: Product Delivery workflow (добавлено 2026-11-24)

К прежним семи skills **добавлены ещё шесть**, теперь всего **13**. Основа — проверенные на предмет наличия и содержания публичные Product Management skill-репозитории, в первую очередь **Anthropic**. **Ни один оригинальный** `SKILL.md` **не скопирован**; мы используем адаптированные самостоятельные инструкции, потому что DeepSeek не исполняет Claude-plugin нативно.

| Skill | За что отвечает | Output |
|---|---|---|
| `07-product-roadmap` | KR→initiative + квартальные value milestones | roadmap, initiative register |
| `08-epic-breakdown` | Инициативы→вертикальные эпики, reuse AS-IS | epics.json |
| `09-prd-write-spec` | Epic→PRD с data/API, flow diagrams, error/rollback | PRD.md |
| `10-agile-story-writer` | Epic/PRD→stories с AC | stories.json |
| `11-story-splitter` | Слишком крупные истории→малые вертикальные slices | split map |
| `12-backlog-quality-gates` | Двусторонняя трассировка KR→story, DoR, capacity | quality report |

**Начните с** `workflows/end-to-end-product-delivery.md`; ссылки на исходные репозитории и границы адаптации в `references/upstream-catalog.md`; тестовый кейс `examples/fictional-service-case.md`.

Команда в API-режиме (необходим доступ ИБ):

```bash
python scripts/run_api.py --source prepared_source.txt --prior approved_stage05.md --stage 07-product-roadmap --out stage07.md --confirm-external-upload
# после согласования roadmap:
python scripts/run_api.py --source prepared_source.txt --prior approved_stage07.md --stage 08-epic-breakdown --out stage08.md --confirm-external-upload
# после утверждения эпиков:
python scripts/run_api.py --source prepared_source.txt --prior approved_stage08.md --stage 09-prd-write-spec --out stage09.md --confirm-external-upload
```

Режим запуска **по одному этапу с human approval**. Модель не выполняет Jira actions. `validate_backlog.py` проверяет структуру ссылок, не доказывает, что stories действительно выполняют KR.

Пример структурной проверки:

```bash
python scripts/validate_backlog.py --epics templates/epic-schema.json --stories templates/stories-schema.json
```

Важно: используйте **подтверждённые версии** исходных KR и техдокументации, не создавайте задачи поверх устаревших бэклогов. Не передавайте внутренние данные в публичный DeepSeek без разрешения ИБ.
