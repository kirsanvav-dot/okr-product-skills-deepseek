# Collision Check
Считать **весь общий файл целей**, а не только авторские строки. Сохранить автора, цветовую подпись (если видна) и source cell. Для каждой пары похожих элементов сравнить: объект результата, единицу метрики/знаменатель, accountable owner, интерфейс, дата, финансирование, первопричину инцидента, источник доказательства.
Метки: `DUPLICATE_OUTCOME` (двойной зачёт одной метрики), `CONFLICT_OWNER` (два владельца за один результат), `SHARED_DEPENDENCY` (одна платформа, разные outcomes), `CAPACITY_COLLISION` (общая роль/ресурс), `NO_CONFLICT`, `UNVERIFIED`.
Не маркировать overlap как конфликт по сходству слов. При известном и подтверждённом разделении работ ставить `NO_CONFLICT + SHARED_DEPENDENCY`, не придумывать новый конфликт. Не объединять «эксплуатационные инциденты» с «DQ-инцидентами» без классификации.
Неполученные планы сторон → `UNVERIFIED`. У каждого конфликта предложить RACI с одним A, критерий уникального зачёта, интерфейс и эскалацию, severity и конкретные ячейки/ссылки.
Пример: инфраструктурная команда отвечает за доступность очереди, продуктовая — за локализацию задержек сообщений. Общая интеграция, но разные результаты и разные знаменатели метрик.
**Выход:** collision matrix, conflict-only shortlist, RACI, no-double-count matrix.
